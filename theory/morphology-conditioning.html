Morphology Conditioning

How to control any robot with a single neural network

Horizon Clarity

Body is a vector — encode any robot's physical structure as a descriptor, condition the policy on it, control any body.

The Problem

A Franka has 7 joints, reaches 0.855m, and weighs 18kg. A UR5 has 6 joints, reaches 0.85m, and weighs 18.4kg. An SO-101 has 6 joints, reaches 0.3m, and weighs 1.2kg.

They're all arms trying to pick up objects. The task is the same. The physical realization is different. How do you train one network to control all of them?

The naive approaches and why they fail

Approach 1: Train separate networks. Works but doesn't transfer. A Franka network has never seen UR5 data → can't generalize.

Approach 2: Concatenate robot ID. One-hot encoding of robot type. Works for seen robots but semantically meaningless → can't interpolate to new robots.

Approach 3: Morphology descriptor (ours). A continuous vector describing the robot's body. Semantically meaningful → can generalize to unseen morphologies by interpolation in descriptor space.

The Morphology Vector

Each robot is described by a fixed-size vector $m \in \mathbb{R}^{46}$ containing:

Morphology descriptor components

ComponentDimensionsWhat it encodes
Link lengths7Distance between consecutive joints
Link masses7Mass of each link
Joint positions (lower)7Lower joint limits
Joint positions (upper)7Upper joint limits
Torque limits7Maximum torque per joint
EE offset3End-effector position relative to last joint
Kinematic type7Joint types (revolute, prismatic, etc.)
Padding1Alignment

Robots with fewer than 7 joints are zero-padded. All values are normalized to $[0, 1]$.

Why continuous > discrete

A one-hot ID is discrete — robot A is either exactly robot A or not. A morphology vector is continuous — a robot with 0.5m reach is between one with 0.3m and one with 0.85m in descriptor space. The network can interpolate.

FiLM Conditioning

Feature-wise Linear Modulation (Perez et al., 2018) is how morphology information enters the network. Instead of naively concatenating the morphology vector to the input, FiLM modulates internal features:

FiLM derivation

Given a feature map $h \in \mathbb{R}^C$ (a channel of the U-Net) and morphology embedding $m$:

$$\text{FiLM}(h, m) = \gamma(m) \odot h + \beta(m)$$

where:

  • $\gamma(m) = W_\gamma m + b_\gamma$ — learned per-channel scale
  • $\beta(m) = W_\beta m + b_\beta$ — learned per-channel shift
  • $\odot$ — element-wise multiplication

Interpretation: Morphology doesn't just add a bias — it controls the gain of every feature channel. It can amplify features relevant to a large arm and suppress those relevant to a small arm.

Why FiLM Over Concatenation?

Information-theoretic argument

Concatenation: $h' = [h; m]$. The network must learn to route information from $m$ through all subsequent layers. If $m$ is 64-dim and $h$ is 256-dim, morphology is 20% of the signal — easily dominated by observations.

FiLM: $h' = \gamma(m) \odot h + \beta(m)$. Morphology directly modulates every feature channel with independent scale and shift. It has a multiplicative effect — even small $m$ changes can dramatically alter the feature landscape.

Analogy: Concatenation is like whispering in a crowd. FiLM is like having the volume knob for every microphone in the room.

Domain Randomization — The Intuition

If you've seen enough variation in training, reality is just another sample from the distribution.

During training, randomly vary physics parameters (mass, friction, damping) within plausible ranges. The policy learns to handle all variations. When deployed on a real robot (with unknown exact physics), it generalizes because reality falls within the trained distribution.

Formal view

Define the simulation parameter space $\xi \in \Xi$. Standard training uses a fixed $\xi_0$:

$$\pi^* = \arg\min_\pi \mathbb{E}_{\tau \sim \text{Env}(\xi_0)}[\mathcal{L}(\pi, \tau)]$$

Domain randomization optimizes over a distribution of environments:

$$\pi^*_{\text{DR}} = \arg\min_\pi \mathbb{E}_{\xi \sim P(\Xi)}\mathbb{E}_{\tau \sim \text{Env}(\xi)}[\mathcal{L}(\pi, \tau)]$$

If reality $\xi_\text{real} \in \text{support}(P(\Xi))$, the policy generalizes.

The Sim-to-Real Gap

DR is necessary but not sufficient. Some physics effects (deformable objects, contact dynamics, sensor noise patterns) are hard to randomize faithfully. The gap remains — DR narrows it, fine-tuning (Week 7) closes it.

Morphology Encoder Architecture

class MorphologyEncoder(nn.Module):
    """
    morph_vec (B, 46) → morph_embed (B, 32)
    Simple MLP with residual connection.
    """
    def __init__(self, input_dim=46, output_dim=32, hidden_dim=128):
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, output_dim),
        )

    def forward(self, morph_vec):
        return self.net(morph_vec)  # (B, 32)

The encoder compresses the 46-dim descriptor into a 32-dim embedding. This embedding is then concatenated with the task embedding (32-dim) to form the 64-dim morphology conditioning vector used by FiLM.
